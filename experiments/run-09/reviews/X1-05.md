## 결점

### 1. `FragmentOffsetBoundsFragment` 내 `offset + expected > total` 조건의 도달 불가능 (죽은 코드)
- **유형**: 죽은 코드
- **어디**: `src/Assembly/Fragments/FragmentOffsetBoundsFragment.cs:54-57`
- **무엇이 어긋나는가**:
  `FragmentOffsetBoundsFragment.Evaluate`의 54행 `if (offset + expected > total)` 조건은 선행하는 43행 `if (offset >= total)`과 `FragmentationHeaderRecord.ExpectedPayloadLengthBytes`의 구현 방식(`remaining = (int)TotalLengthBytes - offset`, `return remaining < uniform ? remaining : uniform`)에 의해 `expected`가 항상 `total - offset` 이하로 산출됩니다. 따라서 `offset + expected <= total`이 수학적으로 항상 성립하므로, 54행의 `DropReason.FragmentOffsetOutOfBounds` 거절 분기는 어떤 입력에서도 절대 실행될 수 없는 도달 불가능한 죽은 코드입니다.
- **재현 방법**:
  임의의 `FragmentationHeaderRecord`와 `arrivedPayloadLengthBytes`를 인자로 하여 `FragmentOffsetBoundsFragment.Evaluate(header, arrivedPayloadLengthBytes, connectionTag, tick)`를 호출합니다.
  1. `offset >= total`인 경우 43~46행에서 먼저 거절됩니다.
  2. `arrivedPayloadLengthBytes != expected`인 경우 49~52행에서 먼저 거절됩니다.
  3. 위 두 검사를 통과한 모든 입력에 대해 `offset + expected <= total`이 항등적으로 참이 되므로 54행의 `DropReason.FragmentOffsetOutOfBounds` 반환 분기에는 도달할 수 없습니다.
- **확신도**: 확신

### 2. `DatagramOpenPipeline.OpenDatagram` 내 `TryParse` 실패 거절 갈래의 도달 불가능 (죽은 코드)
- **유형**: 죽은 코드
- **어디**: `src/Security/Pipelines/DatagramOpenPipeline.cs:93-96`
- **무엇이 어긋나는가**:
  `DatagramOpenPipeline.OpenDatagram`의 1단계(68행)에서 이미 `datagram.Length < EngineConstantsRecord.MinSealedDatagramBytes`(53 B) 여부를 검사하여 53바이트 미만인 입력을 사전에 거절합니다. 그러나 2단계(93행)에서 호출되는 `SealedDatagramHeaderRecord.TryParse`는 오직 `source.Length < WireBytes`(24 B)만을 실패 조건으로 검사합니다. 이미 53바이트 이상임이 보장되어 있으므로 `TryParse`는 항상 `true`를 반환하며, 93~96행의 `DropReason.SealedDatagramLengthOutOfRange` 거절 갈래는 절대 실행될 수 없습니다.
- **재현 방법**:
  임의의 바이트 배열을 `datagram`으로 하여 `DatagramOpenPipeline.OpenDatagram(connectionTag, datagram, sealedArea)`를 호출합니다.
  1. `datagram.Length < 53`인 경우 68~72행에서 먼저 거절됩니다.
  2. `datagram.Length >= 53`인 경우 `SealedDatagramHeaderRecord.TryParse`가 항상 `true`를 반환하므로 93~96행의 분기는 실행되지 않습니다.
- **확신도**: 확신
