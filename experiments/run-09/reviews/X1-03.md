## 결점
### 1. ReassemblyDeliveryPipeline의 슬롯 재사용 검사에서 ConnectionTag 누락으로 인한 타 연결 슬롯 오인 배달 및 자원 조기 반납
- **유형**: 미강제 불변식 / 자기모순
- **어디**: `src/Assembly/Pipelines/ReassemblyDeliveryPipeline.cs:51` (대조: `src/Assembly/Triggers/ReassemblyCompletionTrigger.cs:8-24`, `DEVIATIONS.md:39-43`)
- **무엇이 어긋나는가**: `DEVIATIONS.md` 39~43행 및 아키텍처 규약에서 `ReassemblyId`는 연결별(connection-scoped)로 고유하게 정의되어 슬롯의 전체 식별자는 `(ConnectionTag, ReassemblyId)`입니다. 지연 배달 작업 레코드(`DeferredReassemblyDeliveryRecord`) 역시 `ConnectionTag`를 필드로 보유하고 있습니다. 그러나 `ReassemblyDeliveryPipeline.DrainToApplication`에서는 슬롯 재사용 여부를 검증할 때 `if (slot.ReassemblyId != work.ReassemblyId) continue;`만 확인하고 `slot.ConnectionTag != work.ConnectionTag`는 검사하지 않습니다. 연결이 종료/회수된 후 동일한 `ReassemblyId`를 가진 다른 연결이 해당 슬롯 번호를 재할당받아 사용 중인 경우, 주석의 설명("the slot was reused")과 달리 슬롯 재사용 감지가 무력화되어 새 연결의 슬롯을 오인 배달하고 해당 슬롯 및 버퍼 리스를 조기 해제(`_arena.Release`, `_pool.Return`)하는 자원 파괴가 발생합니다.
- **재현 방법**:
  1. 연결 A(`ConnectionTag = 0xA`)에서 `ReassemblyId = 1`인 메시지의 모든 조각을 수신하여 완성을 달성합니다. `ReassemblyCompletionTrigger`가 `DeferredReassemblyDeliveryRecord(SlotIndex = 0, ConnectionTag = 0xA, ReassemblyId = 1, ...)`를 지연 큐에 파일링합니다.
  2. 다음 `Poll` 진입 전에 연결 A가 종료되어 `ConnectionReassemblyReclamationPipeline.ReclaimConnection(0xA)`가 호출됩니다. 슬롯 0이 회수되어 자유 슬롯 스택(`_freeSlotIndices`)으로 반납됩니다.
  3. 연결 B(`ConnectionTag = 0xB`)가 새 메시지(`ReassemblyId = 1`)를 수신하기 시작합니다. 슬롯 0이 연결 B에 할당되고 조각들이 정상 수신되어 슬롯 0이 완성됩니다.
  4. `Poll`이 호출되어 `Delivery.DrainToApplication(sink)`가 큐에 남아 있던 연결 A의 작업 항목을 꺼내 처리합니다.
  5. 슬롯 0의 상태는 `Open`, `ReassemblyId = 1`, `ConnectionTag = 0xB`입니다.
  6. `slot.ReassemblyId != work.ReassemblyId`는 `1 != 1`로 거짓이 되어 검사를 통과하고, `slot.ConnectionTag`(0xB)와 `work.ConnectionTag`(0xA)의 불일치는 검사되지 않습니다.
  7. 연결 B의 완성 슬롯 데이터가 연결 A의 큐 처리 흐름에서 배달된 후, `_arena.Release(slot)` 및 `_pool.Return(lease)`가 호출되어 연결 B의 슬롯과 버퍼가 즉시 반납/해제됩니다.
  8. 이후 연결 B의 실제 지연 배달 작업이 큐에서 꺼내졌을 때 슬롯 0은 이미 `Free` 상태이거나 제3의 연결에 재할당되어 있어 배달 실패 또는 이중 해제(Double Free)가 발생합니다.
- **확신도**: 확신
