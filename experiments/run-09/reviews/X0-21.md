### 2. K12 불변식 예외 메시지의 인과 진술 반대 (자기모순)
- **유형**: 자기모순
- **어디**: `src/Realtime.Assembly/Stubs/EngineOptions.cs:258-259`
- **무엇이 어긋나는가**: 
  - `EngineOptions.Validate()`에서 K12 불변식(`PerConnectionReassemblyContexts <= PerConnectionReassemblyBytes / ContextOverheadBytes`)을 검사하며, 조건 불만족 시 예외 메시지로 `$"N_conn({PerConnectionReassemblyContexts}) > ⌊B_conn/A_ctx⌋({PerConnectionReassemblyBytes / ContextOverheadBytes}) — 건수 축이 바이트 축보다 먼저 걸릴 수 없다."`를 출력합니다.
  - 수학적으로 $N_{conn} > \lfloor B_{conn}/A_{ctx} \rfloor$가 되면 페이로드가 0인 최소 크기 메시지만 열더라도 바이트 축($B_{conn}$)이 먼저 소진되어 건수 축($N_{conn}$)에는 결코 도달할 수 없게 됩니다. 즉, "바이트 축이 건수 축보다 항상 먼저 걸려 건수 축이 사문화(도달 불가능)되는 문제"를 막기 위한 검사입니다.
  - 그러나 예외 메시지는 `"건수 축이 바이트 축보다 먼저 걸릴 수 없다"`라고 정반대로 설명하고 있어 수식의 실제 의미 및 불변식 의도와 모순됩니다.
- **재현 방법**:
  1. 다음과 같이 $N_{conn} > \lfloor B_{conn}/A_{ctx} \rfloor$가 되는 설정을 생성하고 `Validate()`를 호출합니다:
     ```csharp
     var o = new EngineOptions
     {
         PerConnectionReassemblyBytes = 262_144,
         ContextOverheadBytes = 128, // 262144 / 128 = 2048
         PerConnectionReassemblyContexts = 3_000 // 2048 초과
     };
     o.Validate();
     ```
  2. 발생하는 `ArgumentException`의 메시지를 확인합니다:
     `설정 오류 [PerConnectionReassemblyContexts]: N_conn(3000) > ⌊B_conn/A_ctx⌋(2048) — 건수 축이 바이트 축보다 먼저 걸릴 수 없다.`
  3. 실제로는 바이트 축 262,144 B가 먼저 차서 건수 3,000건에 도달할 수 없는 상황임에도, 메시지는 "건수 축이 먼저 걸릴 수 없다"고 반대로 안내함을 확인합니다.
- **확신도**: 확신

## 결점이 아니라고 판단한 것

1. **`MaxFragmentsPerMessage` ($F=64$)가 하한 경로($D_{floor}, P_{min}$)에서도 도달 불가능한 여유(최대 58조각)인 점**

2. **`MessageSplitter.TryPlan`의 `totalFragments > MaxFragmentsPerMessage` 및 `ReassemblyTable.Offer`의 `slot < 0` 방어 분기**
   - 이유: `EngineOptions.Validate()`의 K4/K12 사전 검증 하에서는 정상 입력으로 도달 불가능한 경로이지만, 향후 설정 변경이나 런타임 방어적 프로그래밍을 위한 의도된 방어 코드로 주석에 명시되어 있으므로 결함으로 보지 않았습니다.

3. **`ReplayWindow` 구조체의 가변 메서드(`Accept`, `ShiftUp`) 호출**
   - 이유: `DatagramOpener` 내에서 `ReplayWindow`는 힙 객체인 `EpochState` 클래스의 인스턴스 필드로 유지되므로, 구조체 메서드 호출 시 복사본이 아닌 힙 필드 상에서 인플레이스(In-place)로 정상 갱신됩니다.
