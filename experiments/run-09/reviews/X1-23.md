## 결점

### 1. 지연 배달 큐 처리 시 재사용된 슬롯의 연결 태그 불일치를 검증하지 않음
- **유형**: 미강제 불변식
- **어디**: `src/Assembly/Pipelines/ReassemblyDeliveryPipeline.cs:50-51` 및 `src/Assembly/Triggers/ReassemblyCompletionTrigger.cs:8-24`
- **무엇이 어긋나는가**: 
  - `DEVIATIONS.md`(39-42행)와 `ReassemblyArenaResource`는 조립 세션의 고유 식별자가 단일 `ReassemblyId`가 아닌 `(ConnectionTag, ReassemblyId)` 쌍이어야 함을 명시하고 있으며, 완료 트리거가 지연 작업 큐에 적립하는 `DeferredReassemblyDeliveryRecord`에도 `ConnectionTag` 필드가 포함되어 있습니다.
  - 그러나 `ReassemblyDeliveryPipeline.DrainToApplication`은 슬롯 재사용 여부를 검증할 때 `slot.ReassemblyId != work.ReassemblyId`만 검사하고 `slot.ConnectionTag != work.ConnectionTag` 검사를 누락했습니다.
  - 이로 인해 특정 연결의 조립 완료 후 슬롯이 회수되어 다른 연결에서 동일한 `ReassemblyId`로 재사용된 경우, 지연 큐에서 이전 연결의 작업 항목을 처리할 때 다른 연결의 슬롯을 이전 연결의 완료 건으로 오인하여 타 연결의 메시지를 조기 배달하고 슬롯 및 버퍼 임대를 조기 반납/파기하는 치명적인 상태 오염이 발생합니다.
- **재현 방법**:
  1. 연결 A(`ConnectionTag = 0xA1`)에서 메시지(`ReassemblyId = 1`)의 모든 조각을 수신하여 조립을 완료합니다. 이때 `ReassemblyCompletionTrigger`에 의해 슬롯 인덱스 `0`과 `(Tag = 0xA1, ReassemblyId = 1)` 정보가 담긴 작업 항목이 `_deferredWork`에 적립됩니다.
  2. 다음 `Poll`에서 `DrainToApplication`이 실행되기 전에 연결 A가 종료/회수되어 `ConnectionReassemblyReclamationPipeline.ReclaimConnection(0xA1)`이 호출됩니다. 슬롯 인덱스 `0`은 회수되어 자유 목록(`_freeSlotIndices`)으로 반납됩니다.
  3. 이어서 연결 B(`ConnectionTag = 0xB2`)가 메시지(`ReassemblyId = 1`) 수신을 시작하여 슬롯 인덱스 `0`을 할당받고 조립을 완료합니다(`slot.ConnectionTag = 0xB2, slot.ReassemblyId = 1, State = Open`).
  4. 이제 `ReassemblyDeliveryPipeline.DrainToApplication`이 실행되어 1단계에서 적립된 연결 A의 지연 작업 항목을 꺼냅니다.
  5. `slot.State == Open`이고 `slot.ReassemblyId == 1`이므로, `slot.ConnectionTag`가 `0xB2 != 0xA1`임에도 검사를 통과하여 연결 B의 슬롯 내용물로 `ReassembledMessageRecord`가 생성되고 싱크에 배달된 후 슬롯이 반납(`Release`)됩니다.
- **확신도**: 확신
