### 1. EngineOptions.Validate()의 K12 검사 오류 메시지와 주석의 논리 모순
- **유형**: 자기모순
- **어디**: src/Realtime.Assembly/Stubs/EngineOptions.cs:254-259
- **무엇이 어긋나는가**:
  - 주석(254행) 및 예외 메시지(258-259행)는 PerConnectionReassemblyContexts <= PerConnectionReassemblyBytes / ContextOverheadBytes 검사가 깨질 때 건수 축이 바이트 축보다 먼저 걸릴 수 없다고 설명한다.
  - 그러나 실제 산술상 {\text{conn}} > \lfloor B_{\text{conn}} / A_{\text{ctx}} \rfloor 되면(예: {\text{conn}} = 3000, B_{\text{conn}} = 262144, A_{\text{ctx}} = 128 \implies \lfloor B_{\text{conn}} / A_{\text{ctx}} \rfloor = 2048$), 페이로드가 0인 최소 크기 메시지만 들어와도 2,048번째 건에서 바이트 축({\text{conn}}$)이 먼저 소진되므로 {\text{conn}}3 0에는 결코 도달할 수 없다. 즉, **바이트 축이 건수 축보다 항상 먼저 걸려서 건수 축에 도달할 수 없게 되는(건수 축이 무의미해지는)** 상태다.
  - 정상 설정({\text{conn}} = 8$)에서는 작은 메시지 유입 시 건수 축이 바이트 축(262 KB)보다 훨씬 먼저(약 1.5 KB 점유 시점) 걸리는 것이 정상이며 의도된 설계다. 예외 메시지의 인과관계 진술이 실제 산술 및 동작과 정반대로 작성되어 있다.
- **재현 방법**:
  ar options = new EngineOptions { PerConnectionReassemblyContexts = 3000, PerConnectionReassemblyBytes = 262144, ContextOverheadBytes = 128 }; options.Validate();를 실행하면 ArgumentException이 발생하며 메시지로 설정 오류 [PerConnectionReassemblyContexts]: N_conn(3000) > ⌊B_conn/A_ctx⌋(2048) — 건수 축이 바이트 축보다 먼저 걸릴 수 없다.가 출력된다. 실제 상황은 바이트 축이 먼저 걸려 건수 축에 도달할 수 없는 상태인데, 메시지는 건수 축이 먼저 걸릴 수 없다고 출력한다.
